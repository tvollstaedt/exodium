# Decisions

## 2026-08-14 - LP matching family-scoped, bundled DB v7
- Decision: Every LP↔EN match (shortcode, thumbnail_key, dosbox_conf, has_thumbnail) goes through `same_group`/`family_expr`; `refresh_catalog` calls the linking step itself after the row copy.
- Rejected: Keeping the thumbnail_key copy in setup.rs - a second copy of the rule had already drifted (unscoped), deleted in favor of `propagate_lp_thumbnail_keys`.
- Why: Titles AND shortcodes repeat across pack families (GK2-DE got the eXoWin9x key, cover 404'd); the catalog refresh restored the broken keys from the bundled DB on every start.
- Gotcha: The bundled DB stamps ITS OWN version; as long as that is older than CATALOG_VERSION, the refresh runs on every start - so fixes have to happen in the refresh itself, not only in migrate().

## 2026-08-19 - Library follows intent, not the disk
- Decision: The automatic scan may now only CONFIRM library entries; `adopt_from_disk` (import, Rescan button, data directory change) is the only way to turn an archive into an entry. Plus `collateral_file_indices`: files whose pieces are all covered by requested files are dropped from the library.
- Rejected: ZIP integrity check and size threshold as detection - collateral is complete and valid (8 MiB piece, eXoDOS archives mostly smaller), so it cannot be recognized from the content.
- Why: Two user reports (4 -> 17 games after one download; four ZZT titles after util.zip). Pass 2 counted every archive >= 1 KB as an installation.
- Gotcha: Collateral cleanup and adoption are opposites and never run together - otherwise the scan removes rows it re-creates one line later. The target size comes from the bundled .torrent, not from `download_size` (which is ZIP + GameData).

## 2026-08-19 - Central engine choice, ECE games optionally under Staging
- Decision: `resolve_engine` is the only place that decides ECE versus Staging (`launch_game`, `game_uses_ece`, `game_printing_unavailable`, panel label). The per-game key `engine = staging` forces Staging; the settings dialog shows the field only if ECE would run at all, and explains the disabled shader switch next to it.
- Rejected: global engine switch (moves 2000+ games on Windows to an untested engine), automatic switching as soon as CRT is on (emulation change as an invisible side effect of a visual setting), hiding the shader field (explains nothing).
- Why: A user set "on" both globally AND per game and went looking for the config file the value was stuck in. With ECE it is not overridden but discarded - ECE has no shader pipeline (of 750 eXo confs with `glshader`, 675 belong to Staging variants, 16 to ece; ECE games get `output=openglnb` plus a scaler).
- Gotcha: `game_engine_info` returns TWO answers - `ece_available` (is there a choice?) and `uses_ece` (what actually runs?). The dialog asks the first: with the second the selection vanished as soon as someone chose Staging, and the way back was gone.
- Gotcha: The engine answer depends on platform, extracted ECE build AND override - the frontend cannot derive it, it asks. The printer note flips to "unavailable" with the override, which is correct: only ECE can print.

## 2026-08-25 - Substituted host paths: no trailing separator, quoting only for mount
- Decision: `to_working_dir` never returns a path with a trailing `/`, and `rewrite_host_paths` wraps a replacement containing spaces in quotes - but only if the line is a `mount`/`imgmount` (`on_mount_line`).
- Rejected: emitting native backslashes on Windows. That blurs the boundary between host path and guest DOS text again, which cost the broken guest `PATH` (1,122 Win3x games).
- Why: Before the `stat()` of the mount target, DOSBox strips only a trailing BACKSLASH (Windows workaround); our `/` slips through, the mount fails, the autoexec runs into its `exit`. Affects 1,570 eXoDOS confs (incl. DOOM II) and 91 eXoWin3x confs, on Windows only - POSIX `stat` accepts the trailing slash, hence invisible on the dev machine.
- Gotcha: Quoting belongs ONLY on command arguments. A config property (`fluid.soundfont=`) reads its value verbatim, so there the quotes would become part of the path.

## 2026-08-30 - One tracker object per download instead of twelve parallel tables (#22)
- Decision: `stores/downloads.ts` keeps a download's state in a `Map<number, Tracker>`; the poll loop schedules itself (`while (!t.cancelled) { await sleep; await tick }`) instead of using `setInterval`. Ending means `endTracker`, which checks identity (`trackers.get(id) === t`) so that a run winding down does not deregister the attempt that replaced it.
- Rejected: `@tanstack/solid-query` - absorbs only the scheduler. Two-signal stall detection, post-install extras phase, torrent validation progress and restart resume would remain domain logic, so the twelve tables stay, plus a new dependency.
- Why: 66 `delete …[gameId]` across six exit paths; a forgotten one leaks state into the next attempt. That is exactly how 9c32855e came about (cancel on a stalled download left the card at its last percentage).
- Gotcha: The generation counter is gone, but the rule is not - every `await` in `tick` must read `t.cancelled` afterwards. And the 5s timer after install now checks `trackers.has(id)`, otherwise it deletes the entry of a download restarted within that window.

## 2026-08-30 - Theme music from the GameData archive: one job core for video and music
- Decision: `media.rs` is parameterized over `MediaKind {Video, Music}` (finder, cache directory, marker, extension); `MusicState` is a second instance of the same job map. Catalog hint `music_file TEXT` (basename from MusicPath, otherwise `<Titel>.mp3` when MissingMusic=false), CATALOG_VERSION 11. Shuffle always over the whole eXoDOS family, exactly one track prefetch, skip silently after 60 s. The frontend cap of 3 streams is shared by video and music (`stores/mediaQueue.ts`, priority foreground video > wanted track > prefetch/background).
- Rejected: a parallel music path (~250 lines of copy with two timeout contracts); `has_music` + extension as two columns; a backfill helper like `populate_manual_paths` (the refresh copies new columns itself); shuffle over the current grid filter.
- Why: Video and theme sit in the same zip, the theme under `Music/MS-DOS/`; for archives up to 8 MiB the video fetch already brings the music piece along. `MissingMusic=false` is a LaunchBox default, not an inventory - Win3x says it 1,120 times and has no file; hence `generate_db` nulls the hint without `gamedata_torrent_index`, and a `.nomusic` marker catches the rest.
- Gotcha: The music cache file keeps its real extension (ServeFile derives the Content-Type from it, GStreamer the demuxer) - so the cache lookup goes by stem. The shuffle never starts at app start.
- Gotcha: The pause reasons are level-driven - `pauseFor` always records a reason, even when nothing was playing, otherwise a track loaded LATER plays over a running game or trailer; that a game started silently does not trigger music on exit is done by `userPaused`, not by the set of reasons. And a "none" with `error` set (OFFLINE_TOKEN) is provisional: neither `music.ts` nor `videos.ts` may cache it as "has no music/no video", otherwise the game is blocked for the session after an offline visit.

## 2026-08-30 - Browse is the jukebox: no music tab, no music collection
- Decision: Filter chip "With theme" (`with_music`) in the Browse toolbar, ▶ only on `GameRow` (list mode); the chip switches the mode for the session without writing `view_mode`. The visible list is the queue (`music.ts` mode `list`): ⏭ follows the current sort, `fetchMoreGames` at the end of a page, stop at the end of the list. `music_cache_index` returns cached IDs and IDs known as "no theme", `put()` keeps the sets live.
- Rejected: third tab (second list over the same rows, own search/sort/paging); pseudo-collection (inherits every `COLLECTION_MAP` projection: pack settings, download buttons, `enable_new_collections`); ▶ as hover overlay on the grid card.
- Why: Every track belongs to a game (stage A per archive, stage B title-based per eXo convention). Genre/search/playlists become music filters for free.
- Gotcha: `with_music` is its OWN EXISTS over the group, not a variant condition - the hint sits on the EN row, the collection filter hits the LP row; combined in one EXISTS the GLP shelf was empty with the chip on. Split cache stems at the LAST `_` (`eXoDOS_GLP_3.ogg`). `playable()` now rejects everything except mp3/ogg, tracker hints no longer reach the shuffle. In theme mode the bar shows an explicit shuffle button instead of ⏮/⏭ - without a queue the skip buttons promised an album, and ⏭ silently started the shuffle. The bar's × hides + pauses (user pause, nothing resumes automatically); the ♪ top-bar button brings it back or, without a track, starts the shuffle. `stop()` remains the internal full reset.

## 2026-09-06 - eXoScummVM: launch via eXo's index, pins as seven builds, variants in the zip
- Decision: `CollectionDef.launcher` (DosBox/Win9x/ScummVm) is the dispatch switch; `commands/scummvm.rs` builds the command line from the bundled `scummvm.txt` (dir -> engine:gameid -> build) and the variant tree in the game folder, runs `--detect` before every start, saves to `<Spielordner>/!saves`. One build per pin: Windows from `utilSVM.zip`, macOS/Linux as content pack `scummvm-<version>`, fallback PATH/Flatpak with a note in the panel.
- Rejected: one ScummVM for all (Thomas: eXo does not pin without reason, goal is "on par with eXoDOS"); variants as catalog rows (833 -> 1,500+, several cards per game, tree only known after unpacking); ScummVM as Tauri `externalBin` (seven builds times 200 MB); saves in the global ScummVM folder (the uninstall backup misses them).
- Why: No per-game conf - eXo itself has one bat plus an index, so all of the §10a mount logic goes away. The root `scummvm.exe` is 2.8.0 (the ini claims 2.6.1), the three git snapshots carry their commit in the version string, hence reproducible.
- Gotcha: Wrong game data does NOT end with exit != 0 but in the ScummVM launcher GUI - hence the `--detect` pre-run. `--no-console` exists only on Windows. `Command::output()` on macOS needs the same fork+exec trick as the emulator spawn (posix_spawn EBADF). The XML merge must put all `<Game>` before the `<AlternateName>`, otherwise "duplicate field `Game`" in the importer.
- Gotcha: `games.platform` stays `ScummVM SVN` for eXo's unstable 109 titles - one collection, two thumbnail runs. Three zips differ from the XML only in letter case; `gen_scummvm_assets.py` rewrites the catalog paths to the zip's spelling because the shortcode is compared exactly against the unpacked folder.

## 2026-09-06 - Support payloads: one `SupportPack` per util zip instead of one pipeline per collection
- Decision: `support_files.rs` carries extraction, watcher, queue and rearm once; `DOS_SUPPORT` and `WIN9X_SUPPORT` are static data sets (suffix, inner zip, prefixes, readiness, post hook), `PACKS` is the list `init_download_manager` rearms over. The rename unit is the prefix in its real spelling (`staged_dir`), running/failed flags hang off the pack.
- Rejected: trait with two impl structs (ceremony for two sets of constants); leaving the DOS pipeline on Windows untouched (would be the third copy with ScummVM's `utilSVM.zip`).
- Why: Both pipelines were identical except for five constants, and ScummVM phase 2 needs a third.
- Gotcha: Windows ECE extraction is covered only by the synthetic test, the field test in the Windows VM is pending. Prefixes are lowercase because the comparison is lowercase - `emulators/86box98/` finds `emulators/86Box98/`.

## 2026-09-06 - Launch pre-step once: `extract_before_launch` for all three launchers, typed zip errors
- Decision: `ExtractError { NotAnArchive, Other }` originates where the zip is opened (`From<ZipError>`: InvalidArchive/UnsupportedArchive = placeholder or fragment); `LaunchError` carries the pre-step's exits and only becomes a string at the command boundary. `launch_zip_candidates` knows both zip locations (collection layout, prefix root) so DOS, Win9x and ScummVM take the same path.
- Rejected: `CommandError` across all 278 `map_err` (too broad, no caller matches outside the launch paths); `thiserror` for two enums.
- Why: Four places matched on `contains("EOCD")`, and three blocks differed only in the candidate list.
- Gotcha: `reset_game_data` stays string-typed (`map_err(String::from)`) because its closure builds its own error texts before unpacking.

## 2026-09-06 - Panel notes as a pure function, Win9x probes as primitives
- Decision: `launchNote(ctx)` in `src/launchNotes.ts` decides from a snapshot (game, platform, engine answers, payload status, pack, job) which ONE note appears above the action bar; `emulatorName`, `isWin9x`, `isScummVm`, `emulatorPackId` live alongside it. `createWin9xStatus(game, settled)` in `components/win9xStatus.ts` bundles engine probe, multiplayer info and payload polling, incl. a re-probe after pack install. The panel now only builds the context and renders.
- Rejected: computing the notes in the backend (texts are UI, and the buttons would still need the signals); a global store for Win9x status (the probes belong to the open panel, not to the app).
- Why: A 200-line if chain over ten signals was untestable; now 15 tests cover the priorities.
- Gotcha: The context is a snapshot per call, yet Solid tracks the signals read because `rawNote` is called inside an effect/JSX. `installPack` gets the collection from the panel because the pack job key is `<collection>:<pack>`.

## 2026-09-06 - commands/ split by responsibility instead of by history
- Decision: games.rs (4.3k) and setup.rs (4.3k) split into `collections`, `paths`, `layout`, `library`, `install`, `assets`; games.rs keeps getters, settings and the DOSBox launch pipeline, setup.rs the wizard, `init_download_manager` and `factory_reset`. Pure moves, one commit per target module, tests move with their function. `mod.rs` still re-exports, lib.rs and the integration tests see no change.
- Rejected: additionally extracting `launch.rs` (games.rs would then be ~1,100 lines; comes the next time the launch pipeline is touched); leaving re-exports of the old paths in games.rs/setup.rs (hidden indirection, exactly the pattern that made the split necessary).
- Why: Both files were catch-alls without a module boundary; every change to download or scan required a search through 4k lines.
- Gotcha: Four helpers became `pub(crate)` for this (`game_op_lock`, `running_games`, `running_game_key`, `copy_dir_recursive`, `extract_game_zip`); they are the shared base of launch, install and library. `prune_gallery_cache_at_startup` is the one entry point into the gallery cache from outside.

## 2026-09-06 - Comment pass: contract instead of history
- Decision: Comments describe what holds (contract, invariant, the one non-obvious reason), at most four lines per function doc; measurements, incidents and rejected alternatives live in DECISIONS.md and the CLAUDE.md paragraphs, in code only as a `(§N)` reference. The rule is now in the Conventions of CLAUDE.md.

- Why: 2,353 lines in blocks of five or more lines, largely narration and repetition of CLAUDE.md; now 119. Net minus 1,947 lines, no code changed.

## 2026-09-06 - zip64 in the range reader (blocker for the Media Pack spike, #27)
- Decision: On the 0xFFFF sentinels, `zip_range::read_central_directory` follows the zip64 locator (20 bytes before the EOCD) to the zip64 EOCD record and reads entry count, directory size and offset as u64; per entry the extra field 0x0001 replaces the overflowed fields in spec order. Directories over 64 MB are rejected (`MAX_DIRECTORY_BYTES`), the 512 MB per-entry cap stays.
- Rejected: the `zip` crate for the directory (synchronous, reads whole pieces over the torrent stream); reading a larger tail instead of seeking a second time (the record need not lie in the tail).
- Why: `DOSSoundtracks.zip` is 36 GB and therefore necessarily zip64; the reader aborted with "zip64 archive not supported".
- Gotcha: The local header is still only skipped (name + extra by length), no zip64 needed there. Test fixtures are hand-built because the `zip` crate writes zip64 only when needed.

## 2026-09-06 - Media Pack spike: DOSSoundtracks.zip is a LaunchBox platform made of stored album zips
- Decision: `zip_range::OffsetReader` (window onto a STORED entry) and `entry_data_offset` are pub so that an album zip inside the 39 GB archive is read with the same tail-first parser. `examples/media_pack_spike.rs` is the tool for it (torrent with empty selection, streamed directory, optional EXTRACT/NESTED). The Media Pack `.torrent` stays outside the repo for now.
- Rejected: loading the album zips whole (median ~150 MB, up to 3 GB - exactly the bulk download that #14 rules out).
- Why: Measured: 584 entries, 126 album zips under `eXo/Soundtracks/`, all STORED; 453 images under `Images/Soundtracks/<Kategorie>/`; `Data/Platforms/Soundtracks.xml` (0.55 MB) describes the albums as LaunchBox "games" (title, composer as developer, notes, CommandLine = album zip). Outer directory in 3-4 s, album directory in 11 s, first track then in 0.1 s; one album costs ~56 MB on disk. Title match album -> eXoDOS game: 54 of 126 exact, the rest needs a hand-made index (compilations, OST suffixes, series).
- Gotcha: Without the empty fastresume bitv, librqbit hash-checks 220 GB of placeholders before `stream_file` is possible ("invalid state: initializing"); the example seeds it like the app. The XML has no link to the game - the mapping has to be built in `generate_db`.

Verified in the dev build with Maniac Mansion (nine chips, switching writes `svm_variant`); the dialog only by test, the UI run was interrupted by an unrelated window.

## 2026-09-06 - ScummVM Phase 2b: pack build in the workflow, release still open
- Decision: `content-packs.yml` gets a `packs` switch (win9x|scummvm) and one matrix over the pins for each. macOS repacks the official DMG (universal, measured on 2.5.0: x86_64 + arm64 - hence both Mac tokens point at the same tarball), Linux compiles from the release tarball like DOSBox-X. Sparkle stays in and is disabled via Info.plist (`SUEnableAutomaticChecks`/`SUAutomaticallyUpdate` false), then re-signed ad hoc.
- Rejected: deleting Sparkle.framework (`scummvm` links it via `@rpath`, the binary then fails to start); Arch packages instead of building from source (would have given up the pins, exactly what §18 prevents).
- Why: Upstream ships only .deb, Flatpak and source for Linux - no binary of a single version.
- Gotcha: The Linux branch is UNTESTED (needs the pkgforge container; an old 2021 pin may fail on the current toolchain). The macOS branch was run through locally for 2.5.0: wrapper `scummvm-2.5.0/`, binary at the resolver path, 6 symlinks preserved, no AppleDouble entries, signature valid, `--version` reports 2.5.0. ScummVM loads themes and engine data at runtime from `../share/scummvm`, quick-sharun bundles libraries only - the data directory is copied by hand in the script and checked by a gate.

## 2026-09-06 - Autoplay no longer overrules the listener; no two download actions side by side
- Decision: The theme autoplay in the panel now starts only if neither `musicUserPaused` nor `playerHidden` is set; otherwise the track is only fetched (`requestTheme`). `playTheme` itself remains, unchanged, the "the user wants this now" function of the ▶ buttons. And the ScummVM note for a NOT installed game is informational instead of blocking ("This game also brings ScummVM X, one-time N MB"), because its download button pulls in the engine anyway - same form as `win9x-support-size`.
- Rejected: making `playTheme` itself respect the dismissal (then the ▶ of a row could no longer start anything after a ×); dropping the note for the not-installed game entirely (the price of the download would then be invisible).
- Why: `playTheme` clears `userPaused` and `barHidden`. The autoplay calls it for every opened game, so the × held only until the next click on a card - reported as "keeps starting again, constantly plays new songs". And the red notice sat directly above a download button that solves the same problem.
- Gotcha: The second part of the music report is NOT fixed - a theme can play for a second or two over a starting preview video, because the video claims the speakers only in its `onPlay` (and not at all in the muted autoplay fallback). Open decision: do not auto-start the theme at all when a video exists.

## 2026-09-07 - E2E via tauri-driver, only in the VM lab, with a preseeded offline state
- Decision: `e2e/` with WebdriverIO 9 against `tauri-driver`, driven by `vm-lab/jobs/exodium.{sh,ps1}` after the debug build (Linux under Xvfb, Windows in the interactive session via `schtasks /it`). `examples/e2e_seed.rs` copies the bundled DB into the real app directory and writes `data_dir`, `root_folder`, `network_mode=offline`, `seeding_enabled`, `welcome_seen`, `collections` - no wizard, no torrent, no dialog over the grid. Twelve `data-testid` as anchors; all specs run in ONE session (`specs: [[...]]`), the driver starts once in `onPrepare`.
- Rejected: selecting via CSS classes (style hooks, break silently); GitHub CI (xvfb and driver versions without interactive investigation); a custom WebDriver client (waiting/retrying would have to be built by hand); driving the wizard via OS automation (native file dialog, different on each platform).
- Why: macOS has no WebDriver for WKWebView, so E2E exists only in the VMs. The two findings the lab has delivered so far (startup and render path) are exactly the class that a smoke test without network covers.
- Gotcha: **Windows: the main window is created in `setup()` (`create: false` in both configs), because msedgedriver requests the debug port via `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` and WebView2 ignores the variable as soon as the app sets its own arguments - wry always does.** Measured: `WEBVIEW2_USER_DATA_FOLDER` takes effect, the arguments variable does not (no `DevToolsActivePort`, port closed). The app appends the variable's value to wry's default arguments only when it is set; otherwise the window is identical. The seeder overwrites the REAL database (Tauri derives the directory from the identifier) - hence the `EXODIUM_E2E=1` guard. `$$()` in WDIO 9 freezes its result after the first `await`; inside `waitUntil`, query again on every iteration. After `deleteSession`, tauri-driver answers a second session only with hyper `SendRequest` errors. The card's click handler sits on `.game-card-art`, not on the card, and the art has NO height until its cover has loaded - wait for the `<img>`, not for the card (so a card without a loadable cover has no click area for users either; open). After a search the OLD first card persists until the result arrives - "a card exists" proves nothing, wait for the title. A catalog search takes 5-10 s on the Windows guest (Linux: under 1 s; half of that was Defender on `%APPDATA%`) - `waitforTimeout` 60 s, and the latency on real Windows hardware is an open measurement. `ring` requires clang on Windows ARM64. pnpm 12 rejects packages younger than 24 h (`minimumReleaseAge`) - the jobs pin 10.27.0.

## 2026-09-07 - A file length proves nothing on a torrent tree
- Decision: Everywhere a size served as proof of completeness, the code now asks the session: the startup scan gets the `in_flight` set (selected && !complete) and resets `installed` rows that were confirmed that way; `extract_before_launch` refuses an archive the session is still filling (`StillDownloading`); the support watcher uses the on-disk size only without a session handle and counts failed attempts only when completeness is confirmed; `support_files::status` reports verified bytes; the layout migration decides a size tie by which archive can be opened. Downloads survive a restart: `list_active_downloads` + `resumeDownloads` recreate the trackers - it is the poll that unpacks at the end. An `.extracting` lock older than 5 min counts as a crashed extraction: row back to `installed = 0`, lock removed, the tracker unpacks again.
- Rejected: replacing the size with the allocated blocks (Windows has no portable API for it); persisting a second "downloading" state (librqbit's selection IS that state).
- Why: librqbit creates files sparse; after the first piece the file has full length. Measured in the lab: half-downloaded games on the "Installed" shelf, extraction on half archives (`EXTWin9x.zip not found inside`, `Invalid checksum`), after three attempts `failed` until restart.
- Gotcha: Support prefixes must name what the pack OWNS - `emulators/dosbox/` holds eXoDOS' ece builds AND eXoWin9x' x98, and a prefix on the parent folder deleted the ECE builds on every Win9x extraction (test `a_pack_leaves_its_siblings_under_a_shared_parent_alone`). A prefix may now also be a file. `sweep_leftovers` clears `.support_staging_<pid>`/`*.support_tmp_<pid>` of other processes (2.9 GB after two hard stops).

## 2026-09-07 - ScummVM: a pack for the platform beats any system copy
- Decision: `resolve_scummvm` falls back to PATH/Flatpak only if the manifest knows NO pack with the pinned version for the running platform. Otherwise it counts as "not present", the panel names the pack size, `download_game` fetches it along with the game. Linux packs are now built per architecture (`scummvm_arches`, aarch64 on GitHub's ARM runners, the pkgforge container is multi-arch).
- Rejected: preferring the system copy and merely offering the pack (how it was) - in the lab an apt ScummVM ran instead of the pin, and the hint "your system's ScummVM will run it instead" is an error for the user, not an offer.
- Why: eXo pins because games break across releases; a system copy is not a solution but the very state the packs are meant to end.
- Gotcha: Without a pack for the platform (today: everything except darwin-*, linux-x86_64, linux-aarch64) the system remains the only way, and the scummvm.org hint is honest there.

## 2026-09-08 - ScummVM: platform codes translated, multi-part Glk games pinned to part 1
- Decision: `platform.txt` carries eXo's abbreviations (`sp48`, `st`, `dos`), ScummVM wants its own (`zx`, `atari`, `pc`) and otherwise discards the whole command line - `scummvm_platform_code` translates, unknown values leave `--platform` out. ## 2026-09-25 - pdf.js: legacy build instead of modern build
- Decision: `PdfReader` imports `pdfjs-dist/legacy/build/pdf.mjs` and the legacy worker (+190 KB / +170 KB, lazily loaded).
- Rejected: own polyfills for `Promise.try`/`withResolvers`/`toBase64` (the worker is a separate context, they would have to go there too, and the list grows with every pdf.js release).
- Why: Reddit report, manuals and magazines don't load on the Mac. - Gotcha: pdf.js officially names Safari 18+ for the legacy build; the core-js polyfills reach further in practice, but it is not promised.

## 2026-10-02 - Poster and content-pack commands release the DB mutex before touching the filesystem
